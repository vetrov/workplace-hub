# Foundation contracts

## Internal mock HTTP

These are in-app HTTP contracts, not external services. Responses are generated by an interceptor.

| Method/path | Input | Result |
| --- | --- | --- |
| GET `/api/requests` | `q`, `sort`, `page`, `pageSize`; selected demo identity | `{ items: RequestSummary[], total, page, pageSize }` after visibility filtering |
| GET `/api/assets` | Same query shape and identity | `{ items: AssetSummary[], total, page, pageSize }` after visibility filtering |
| GET `/api/dashboard` | Selected demo identity | Counts derived from that identity's visible request/asset records |

Request search matches title/id; asset search matches name/id, case-insensitively. Allowed request
sorts: createdAt ascending/descending and title ascending/descending; default createdAt descending.
Allowed asset sorts: name ascending/descending and status ascending/descending; default name ascending.
Use id as a deterministic secondary sort. Page beyond the final page normalizes to the last available
page; zero results use page 1. Invalid query values normalize to defaults. Query changes reset page to 1.

The interceptor obtains identity from the session service; no authentication token is sent or required.
Invalid identity yields 403. Unknown `/api/` paths yield 404. Scenario error yields 503 with a readable
message. In this feature, unsupported mutation methods yield 405. No API path is forwarded remotely.

Normal artificial delay: 250 ms. Delayed mode: 2,000 ms. Empty mode returns an empty items array
and total zero. Error mode persists until retry selects normal mode; retry does not reset business data.
Cancellation and generation validation prevent obsolete records from being displayed.

## UI and reset

Implemented routes: `/dashboard`, `/requests`, `/assets`, `/preferences`, plus helper pages.
Root redirects to Dashboard. Other business screens remain explicitly planned navigation items.

Reset recreates seeds, sets normal mode, increments scenario generation, and restores active list
search/sort/page defaults. Preserve selected identity and display preferences. Clear old results
immediately on identity/scenario changes.

Preference storage uses a versioned key, `workplace-hub.preferences.v1`; demo identity uses
`workplace-hub.identity.v1`. Validate saved values and fall back safely. Storage failure must not
block rendering or preference changes; show that changes apply for the current session.
